## 0. 结论

1. 判定不用 YOLO 置信度：**固定相机 + 颜色分割 + 与金样板的几何比对**，输出可解释的毫米与角度。
2. 新增第 4 页签「针床检测」，调试/执行两套界面，共用一套判定内核。
3. 阈值不写死：配方里存 dxMm / dyMm / dThetaDeg 等，标定后填入；试跑建议 5–8mm、3.5°–5.6°，稳定后再收紧。
4. 相机常驻、手动单次触发；不存图，内存只留最近 20 条结论。
5. 首版约 **9.5 人日**；不做浮高/翘脚、异物 AI、PLC 硬联锁、多相机、MES。

---

## 1. 背景与目标

FCT 测试前，产品放到针床上，若放歪、放偏，压合时可能压坏针或产品。需要在压合前给操作员一个明确的 OK/NG 结论，并在 NG 时说明原因（偏 X、偏 Y、旋转、没放、放多件、看不清）。

目标：

- 单次手动触发，**300ms 内**给出结论；
- 结论可解释（给数值，不只给百分比）；
- 换机种只换配方，不改代码；
- 相机、曝光、阈值异常时**不能出假 OK**。

非目标（首版）：

- 不检测浮高、翘脚、引脚变形；
- 不做异物/脏污 AI；
- 不与压机做硬联锁（预留信号）；
- 不支持多相机同时判定。

## 3. 判定原理：为什么不用 YOLO 置信度

界面上的「匹配度」是 YOLO 的置信度，不是图像相似度。它回答的是「这里有没有一个像训练样本的目标」，而不是「这个目标相对金样板偏了多少毫米」。只拿正确放置的图训练，模型没有「歪」的负样本，也就没有决策边界；再加上 CNN 的平移不变性和训练增强，产品挪 10–20mm 往往仍然是高置信度。

| 维度 | YOLO 置信度 | 几何比对（本方案） |
|---|---|---|
| 输出 | 0–1 分数 | dx/dy(mm)、dθ(°)、面积比、越界量 |
| 对平移 | 不敏感 | 直接测出 |
| 阈值含义 | 无物理意义 | 就是公差 |
| 可解释性 | 低 | 高，可画在图上 |
| 训练依赖 | 需标注与训练 | 只需一张金样板 |

结论：YOLO 保留在「识别测试」页做型号/异物辅助，针床检测页不加载 YOLO，纯 OpenCvSharp。

## 4. 方案总览

数据流：

    USB 相机 ──常驻线程──▶ 最新帧缓存 ──▶ 预览（15fps）
                                        │
                          手动触发 ────▶ 抓拍稳定帧
                                        │
                          质量闸门 ──▶ 颜色分割 ──▶ 轮廓/最小外接矩形
                                        │
                          与金样板配准 ──▶ 几何量 ──▶ 规则判定
                                        │
                                  OK / NG + 原因码 ──▶ 画面叠加 + 结果区

判定链六步：

1. 取帧：丢弃触发前的旧帧，连取 3 帧取中位（可选），确认画面稳定；
2. 质量闸门：亮度、过曝比例、对比度、模糊度，任一项不合格直接 NG(LOW_QUALITY)，不出 OK；
3. 分割：HSV 区间分割 + 形态学，取最大轮廓；
4. 配准：以金样板为基准，按质心平移、按主方向旋转；
5. 测量：dx、dy、dθ、面积比、IoU、最大轮廓偏差、安全区越界量；
6. 判定：任一超差 → NG + 原因码；全部通过 → OK。

## 6. 相机与采集

### 6.1 常驻线程

- 打开一次 VideoCapture，后台线程 Grab + Retrieve，只保留最新一帧（Mat + 时间戳 + 帧号）。
- UI 用 15fps 定时器取克隆帧显示，避免 30fps 刷新拖慢界面。
- 进入页面时打开，离开页面时停止并释放；异常时置 Error 状态，UI 显示红色横幅。

不复用 MainForm.Capture.cs:503 的 GrabCameraSnapshot()：它每次 new VideoCapture 再 Release，单帧可用但不适合预览，且 3 秒超时会卡 UI。新写 FixtureCamera，接口：

    Open(FixtureCameraConfig) -> bool
    TryGetLatest(out Mat frame, out long frameId) -> bool
    Close()
    IsOpen / LastError

### 6.2 参数与锁曝光

- index、分辨率、FOURCC 在打开前设置；设置失败则回退默认并提示。
- 曝光/增益通过 CAP_PROP_EXPOSURE / CAP_PROP_GAIN 尝试写入；多数 UVC 驱动不支持，失败时提供「打开驱动属性页」按钮（CAP_PROP_SETTINGS），由人工手动关自动曝光。
- 优先级：YUYV > MJPG。USB2 带宽不够时 1080p 可能只有 5fps，手动判定可接受；帧率低于 5fps 时提示降分辨率。

### 6.3 与采集页的互斥

- 相机同一时间只允许一个页面持有。
- 进入针床检测页：若采集页已打开相机，提示「识别测试页正在使用相机，是否释放并切换？」，确认后关闭采集页相机。
- 离开针床检测页：释放相机，恢复采集页可用。
- 释放失败（驱动未回收）时提示重启程序，不要静默失败。

## 7. 标定

### 7.1 两点标定（首版默认）

1. 在预览图上点两个点；
2. 输入两点实际距离（mm），建议 ≥100mm；
3. 计算 mmPerPixel = 实际距离 / 像素距离；
4. 连续做 3 次取中位数，离散度 >2% 时提示重做；
5. 写入 recipe.calibration。

优点：不需要标定板，现场 2 分钟完成。缺点：不校正镜头畸变，视场边缘有 1–3px 误差；在 10mm 级公差下可忽略。

### 7.2 棋盘格标定（可选）

- 提供棋盘格图（可打印），输入方格边长与行列数；
- 计算内参、畸变系数与 mm/px；
- 存 calib.json，判定前 undistort；
- 首版只做「比例 + 可选去畸变」，不追求亚像素级重投影精度。

### 7.3 有效性校验

判定前检查：

- mmPerPixel 存在且 >0；
- 标定时间距今超过 30 天 → 警告（不阻断）；
- 当前分辨率与配方记录不一致 → 按比例换算 ROI，并提示重新标定；
- 标定值与空图基准偏差过大 → 提示「相机可能被移动」。

## 9. 判定算法

### 9.1 流水线

1. **取帧**：触发后最多等 300ms 拿一帧新帧，帧号必须大于触发时的帧号；
2. **质量闸门**：平均灰度、过曝比例、对比度、拉普拉斯方差（模糊）；不过 → LOW_QUALITY；
3. **ROI**：按归一化 ROI 裁剪；
4. **分割**：RGB → HSV，按板色设 2–3 个区间，形态学开闭，取最大连通域；
5. **轮廓**：findContours + minAreaRect + 矩（质心）；
6. **配准**：先按质心平移对齐金样板，再按 minAreaRect 角度差旋转；
7. **测量**：见 9.2；
8. **判定**：见 9.4。

### 9.2 几何量定义

| 量 | 定义 | 单位 |
|---|---|---|
| dx, dy | 产品质心相对金样板质心的位移 | mm |
| dθ | minAreaRect 主方向差（归一化到 −90–90） | ° |
| areaRatio | 产品面积 / 金样板面积 | — |
| IoU | 对齐后产品掩膜与金样板掩膜的 IoU | — |
| zoneOverflow | 产品轮廓越出安全区的最大距离，未越界为 0 | mm |
| contourScore | 轮廓面积/凸包面积 × 边界平滑度，用于判断分割是否可信 | — |

注：dx/dy 是「相对金样板」的位移；如果金样板本身放得偏，需要在采金样板时确认位置，或用安全区兜底。

### 9.3 默认阈值（占位，标定后填入）

| 参数 | 试跑值 | 说明 |
|---|---|---|
| dxMm / dyMm | 5.0 / 5.0 | 压损边界 >10mm，先取一半 |
| dThetaDeg | 3.5 | 压损边界 >7°，先取一半 |
| areaRatio | 0.90–1.10 | 板批次差异大时放宽 |
| iouMin | 0.85 | 形状/遮挡异常时下调 |
| zoneMarginMm | 5.0 | 安全区外扩 |
| minContourScore | 0.60 | 低于此值判 LOW_QUALITY |

阈值写入配方，不在代码里出现字面量；代码只保证可配置、可回滚。

### 9.4 原因码与优先级

按顺序判定，命中即停：

| 优先级 | 原因码 | 中文提示 | 触发条件 |
|---|---|---|---|
| 1 | CAMERA_LOST | 相机未连接/取帧失败 | 打不开或超时 |
| 2 | LOW_QUALITY | 画面过暗/过曝/模糊 | 质量闸门不过 |
| 3 | NO_PRODUCT | 未检测到产品 | 最大轮廓面积 < 金样板 20% |
| 4 | MULTI_OBJECT | 画面中有多个物体 | 第二大轮廓 > 最大轮廓 15% |
| 5 | OUT_OF_ZONE | 产品超出安全区 | zoneOverflow > 0 |
| 6 | SHIFT | 位置偏移超差 | dx 或 dy 超差 |
| 7 | ROTATION | 旋转超差 | dθ 超差 |
| 8 | AREA_DEFECT | 面积异常 | areaRatio 越界 |
| 9 | SHAPE_MISMATCH | 形状不匹配 | IoU 或 contourScore 不足 |
| 10 | CALIB_INVALID | 标定缺失/失效 | 无 mmPerPixel 等 |
| 11 | RECIPE_MISMATCH | 配方与相机不匹配 | 分辨率不符且无法换算 |

SHIFT 在提示里再细分「偏左/偏右/偏上/偏下」，便于操作员调整。

### 9.5 安全区

安全区的目的：即使 dx/dy 没超差，只要产品有任何部分伸进「会压到针」的区域，也必须 NG。

- 默认由金样板掩膜外扩 zoneMarginMm 生成；
- 若后续能标定针尖坐标，改成多边形 safetyZone，直接算产品轮廓到针尖的最小距离；
- 首版先做「外扩矩形/轮廓」，不依赖针尖坐标。

## 10. 状态机

| 状态 | 进入条件 | 允许操作 | 下一状态 |
|---|---|---|---|
| Idle | 未打开页面 | — | Preview（进入页） |

| Judging | 取帧成功 | — | Result / Error |

| Debug | 切到调试 | 改参数、采图、标定、测试 | Preview |
| Error | 相机/配方异常 | 重连、切机种 | Preview |

执行模式下的 Result 会保留到下一次判定，不会因为预览帧刷新而消失；但一旦进入 Error，结果必须清空并显示「无画面」。

## 11. 异常与兜底

| 异常 | 处理 | 是否允许 OK |
|---|---|---|
| 相机打开失败 | 红色横幅「相机未连接」，判定按钮禁用 | 否 |
| 取帧超时（>500ms，重试 3 次） | 转 Error，提示检查 USB/驱动 | 否 |
| 连续 5 帧全黑/全白 | LOW_QUALITY，提示检查光源/镜头盖 | 否 |
| 画面与空图差异过大 | 警告「相机或治具可能被移动」，要求重采空图 | 调试模式可继续，执行模式禁止 |
| 标定缺失 | 禁止判定，提示先标定 | 否 |
| 配方缺失/损坏 | 提示重建配方，保留旧版本备份 | 否 |
| 保存失败（只读/占用） | 提示失败，当前判定结果仍有效 | 是（仅本次） |
| 分辨率与配方不符 | 尝试按比例换算 ROI；换算失败则 RECIPE_MISMATCH | 否 |

核心原则：**看不清就不出 OK**。任何异常都收敛到「禁止判定」，而不是沿用上一帧结论。

## 12. 多机种

- 机种目录 fixtures/<MODEL>/，机种号由用户输入（字母数字，2–16 位）；
- 下拉列表读取目录，显示 name + version；

执行模式按 ConfirmFrames 连续取帧，任一帧 NG 立即 NG，全部 OK 才 OK，避免单帧抖动。

### 首版默认值（都可在页面改）

- 相机：USB index 0，1280×720，MJPG，曝光/增益留空（由驱动自动）
- 公差：dx/dy 5mm，dθ 3.5°，面积比 0.90–1.10，IoU ≥0.85，安全区外扩 5mm，轮廓分 ≥0.60
- 质量闸门：平均灰度 35–225，对比度 ≥12，高光比 ≤0.08
- 确认帧：1（先调通，再按现场抖动加到 2–3）

这些是「能跑起来」起点，不是验收值；判定线请按 20 节第 1 条现场试跑后收紧。

### 真机验证步骤

1. 关闭正在运行的 YoloFool，重新启动（旧进程会锁 exe，导致编译产物不是最新）。
2. 切到「针床检测」页 → 相机页签 → 应用并打开：右侧应出现实时画面，左下角显示帧尺寸与帧率。
3. 若打不开：确认「识别测试」页是否正在用同一相机；换 index；或先在驱动属性页锁曝光。
4. 标定页签：点「画参考线」，在画面里沿已知长度的治具边画一条线，输入实际毫米数 → 得到 mm/px；误差应接近 0。
5. 模板页签：先放空治具采「空图」，再放金样板采「金样板」；采金样板时会自动估计 HSV 区间并生成掩码，掩码预览应贴合板轮廓。
6. 取景区：画一个比金样板略大的框（建议外扩 10–20mm），超出 ROI 的产品直接 NG。
7. 调试页签 → 单张测试：正确放置应 OK，平移到 6mm / 旋转 4° 应 NG，且原因码与偏移方向一致。
8. 切到执行模式 → 开始检测：只保留大结果和开始/停止，参数不可改；连续放 20 次正确、20 次歪放，记录漏判/误判。

### 已知边界

- 不做浮高/翘脚、异物识别、PLC 硬联锁、多相机、MES；权限/自检/统计/异常兜底只留扩展点。
- 不做亚像素级 0.1mm 判定：默认判定线是 5mm 量级，0.1mm 需先满足 ≤0.03mm/px 与 σ≤0.02mm 重复性。
- 首次运行会以默认参数建档；若相机/治具被移动，需重采空图，否则空图校验会提示。
- 判定依赖颜色分割，板面颜色与治具对比度不足时，先调阈值页的 HSV 区间，再看是否换背光。

### 相机启停、拍照与右键菜单（2026-11-18 补充）

- **默认不开相机**：进入「针床检测」页不再自动占用摄像头；点工具栏「打开相机」才启动，离开页签自动释放，避免与「识别测试」页抢同一台设备。
- **打开相机无响应已修复**：原工具栏按钮没有绑定事件（只有相机子页里那个局部按钮有），现在工具栏与子页共用同一异步打开逻辑（YoloFool/UI/MainForm.Fixture.cs 的 OpenFixCameraAsync）；打开期间按钮禁用、鼠标转等待，2.5 秒内无首帧会明确提示。
- **拍照（只进内存）**：定格当前帧到界面，状态栏显示「已拍照（仅内存，未保存）1280×720」，按钮变「重拍」；「恢复预览」回到实时画面并丢弃这张照片；「单张测试」优先判定这张定格照片，便于把歪放样件拍下来复现。
- **右键菜单与识别测试页共用**：保存图片…（原图）/ 保存画面…（带识别框）/ 复制图片 / 适应窗口；实现在 YoloFool/UI/MainForm.Capture.cs 的 BuildImageContextMenu(ImageCanvas, …) 与 SaveImageAs(…) 重载，两个画布走同一套保存/复制逻辑。
- **已验证**：打开相机 → 拍照定格 1280×720 → 关闭相机 → 再次打开成功；右键「复制图片」后剪贴板得到 1280×720 图像。

### 标定/标定线/模板缩略图/重拍修复（2026-11-18 第二次补充）

- **标定保存**：mm/像素 与参考线原本已写入 recipe.json，但重启后内存里的参考像素长度 `_fixCalibPx` 归零，「重算并保存」会提示“还没有拾取两点”。现在把标定线两端像素坐标存进配方的 `calibration.lineAX/lineAY/lineBX/lineBY`，启动时 `RestoreCalibrationLine()` 恢复；「重算并保存」在没有新拾取时直接用 `refLengthPx` 重算。验证：重启后点「重算并保存」→「标定已保存：0.0845 mm/像素（参考 100.0 mm）」。
- **标定线不再常驻**：ImageCanvas 新增 `LineLabel`（针床页设为“标定线”）；`ShowCalibLine(bool)` 统一控制。实时预览、恢复预览、判定结果出来后都会隐藏；只有拾取两点、保存标定、查看模板、采集完模板时才显示。
- **模板缩略图**：调试模式右侧顶部新增「空治具 / 金样板」两张缩略图，随采集/切换机种刷新；点击后把模板显示在左侧画布并叠加标定线，状态栏提示“正在查看…模板；点恢复预览回到实时画面”。
- **采集模板会重新拍照**：原实现只写文件不回显；现在先退出定格状态，用帧号水位线 `_fixFrameWatermark` 取点击之后的新帧（不拿缓存旧帧），采完立即把这张模板显示在左侧。采集中按钮禁用，避免连点。
- **重拍偶发无效**：三类原因——判定中按钮被静默忽略、取帧超时没有任何提示、上一次定格未清理导致复用同一帧。现在：判定中点「重拍」提示“正在检测，完成后再拍照”；重拍前先丢弃旧定格；`WaitFreshFrame(1500ms)` 超时后退回 `TryGetLatest` 最新缓存帧，仍无画面才报“拍照失败：没有取到画面…”。打开/关闭相机会重置帧号水位线，避免重开相机后帧号回绕。
- **已验证**（buildcheck + 本机虚拟相机）：打开相机 → 拍照 → 重拍 均返回“已拍照（仅内存，未保存）1280×720”；点金样板缩略图能显示模板与标定线；重启后重算并保存成功。

### 模板采集顺序无关（2026-11-18 第三次补充）

- **问题**：先采金样板、后采空治具时，金样板掩码是在没有空图差分的情况下算的；补采空治具只写文件、不重建掩码，空图差分等于没生效。
- **改法**：CaptureTemplateAsync 不再“只有采金样板才建掩码”。每次采完（空治具或金样板）都从磁盘读回两张模板，只要金样板存在就按当前两张重建一次 golden_mask.png；分割参数只在采金样板时重新估计（它只跟金样板和 ROI 有关，与空治具无关）。
- **结果**：空治具 / 金样板谁先谁后都成立。先采金样板 → 掩码先只按颜色；补采空治具后自动补上差分。先采空治具 → 采金样板时直接带上差分。状态栏和「模板」页会显示还缺哪张、掩码是否含空图差分。
- **仍然建议**：改 ROI、动相机机位、换光源之后，按「用金样板重建分割参数」重算一次，保证 HSV 范围也是按新 ROI 估计的。

### 调试面板布局与文字遮挡调整（2026-11-18 第四次补充）

- **问题**：右栏固定 400px，扣掉 TabPage 内边距与滚动条后只剩约 376px；相机页「格式 / MJPG」被右边缘截断，底部三个按钮只露出上半截；标定页「实际长度 mm」与数字框挤在一起，「重算并保存」显示成「重算并」。日志列表 5 列合计 424px，也出现横向滚动条。
- **改法**（YoloFool/UI/MainForm.Fixture.cs）：
  - 右栏宽度 400 → 440，判定标签高度 96 → 80，日志区 190 → 116；
  - 相机页拆成 4 行：序号 + 分辨率 / 格式 / 手动曝光 + 曝光 + 增益 / 三个按钮；按钮宽度「应用并打开」「驱动属性页」各 104、「框选检测区 ROI」148；
  - 标定页拆成两行：拾取两点 + 实际长度 + 数字；「重算并保存」单独一行；
  - 标签换行宽度按页区分：相机页 340，标定页 372（340 时“已标定 …（参考 100.0 mm / 1041.1 px）”会把 “(px)” 折到下一行）；
  - 日志列宽：时间 62 / 结论 46 / 原因 138 / 偏移 98 / 耗时 56，合计 400；
  - 行容器统一 `AutoSizeMode = GrowAndShrink`，避免行按最大历史宽度占位。
- **结果**：5 个调试子页均无横向滚动条，按钮与标签文字完整；用 UIAutomation 切页 + 截图逐页核对。

### 判定履历与轮廓分下限（2026-11-18 第五次补充）

- **履历落盘**：每次判定（OK/NG 都写）追加一行到 `fixtures/<机种>/history/history-YYYYMMDD.csv`，列为 time, ok, reason, dx_mm, dy_mm, dtheta_deg, area_ratio, iou, overflow_mm, contour_score, confidence, elapsed_ms, frame_w, frame_h。实现在 `YoloFool/Core/Fixture/FixtureHistory.cs`，由 `ShowFixResult` 调用；写失败不影响判定。
- **轮廓分下限可调**：原「充实度下限」只存在 recipe.json 里（默认 0.60），界面改不了。现在「阈值」页新增「轮廓分下限」，与「高光比例上限」同一行；新建配方的默认值降到 0.50（老配方保持原值，需在界面里改）。
- **为什么调**：现场日志显示 SHAPE_MISMATCH 的充实度集中在 0.59–0.70，而当前金样板自身充实度只有 0.6757，距 0.60 仅 0.076 余量，单帧抖动就会越线。
- **相对基线（同日补充）**：「阈值」页新增「充实度允许下降」（默认 0.10）与只读的「金样板 0.676」显示。判定下限改为 `max(轮廓分下限, 金样板充实度 − 允许下降)`，配方字段 `tolerance.contourScoreDrop`。金样板重采后基线自动更新；把「轮廓分下限」降到 0.50 后，当前机种的判定下限约为 0.576。

### 阈值页 A 方案：滑块 + 预设 + 高级参数（2026-11-18 第六次补充）

- **动因**：原阈值页是一屏 15 个数字框（X/Y 公差、角度、IoU、面积比、安全区、质量闸门、轮廓分、充实度下降），现场人员不知道每个值调大调小会怎样；用户要求改成“一行一个值 + 说明/tooltip”的可读形式。
- **常用层**（打开“阈值”页直接看到）：
  - 位置允许偏移 ±mm：滑块 0.5–15（步进 0.5），数字框联动；调大更容易放行轻微歪放，压损边界约 10mm，建议 3–8mm。
  - 角度允许偏转 ±°：滑块 0.5–10（步进 0.5），数字框联动；压损边界约 7°，建议 2–5°。
  - 形状严格度：宽松 / 标准 / 严格 / 自定义，对应 IoU 0.80 / 0.85 / 0.90 与充实度允许下降 0.15 / 0.10 / 0.05。
  - 确认帧数 1–10（默认 1），连续 N 帧 NG 才报警。
  - 每行下面一句影响说明；滑块、数字框、形状下拉、确认帧都有 tooltip（ToolTip，9000ms）。
  - 预设按钮：宽松 = 8mm / 5° / IoU0.80 / drop0.15；标准 = 5mm / 3.5° / IoU0.85 / drop0.10；严格 = 3mm / 2° / IoU0.90 / drop0.05。一键把三组常用值写入控件。
  - 底部“当前：位置 ±5 mm / 角度 ±3.5° / IoU ≥0.85 / NG 即报警”摘要，随控件实时刷新。
- **高级层**：「高级参数 ▾」折叠区，保留原数字网格：X 公差 / Y 公差、IoU 下限、安全区外扩、面积比下限/上限、最暗均值、对比度下限、高光比例上限、轮廓分下限、充实度允许下降、只读“金样板 0.676”。展开后自动滚到高级区，按钮变成“收起高级参数 ▴”。
- **联动规则**：滑块 ↔ 数字框双向同步；位置滑块同时写 X/Y 两个公差；角度滑块同时写角度字段；高级层改 IoU 或充实度下降时，形状下拉自动匹配“宽松/标准/严格”，不匹配则显示“自定义”。
- **不自动保存**：所有改动只作用于界面；必须点「保存阈值」才写 recipe.json（与原行为一致），避免误拖滑块直接改现场配方。
- **验证**：UIAutomation 切到“阈值”页截图（常用层、展开高级层）、点「宽松」→ 位置 8.0 / X/Y 8.00 / IoU 0.800 / 角度 5.0，点「标准」→ 5.0 / 0.850 / 3.5；高级网格无横向滚动条，金样板 0.676 正常显示。

### 安全区（像素）判定模式（2026-11-18 第七次补充）

- **动因**：形状模式的面积比 / IoU / 充实度是对整块掩码的全局统计，板内反光、白标签、压块都会让数值抖动；用户提出“不标定、不用 mm，把边缘画成线，产品必须留在里面，用像素”。
- **判定量**：产品最大轮廓（鲁棒外沿取 1%/99% 分位，避免噪点）与矩形安全区比较：越界像素数、最大越界深度、四边最小余量（px）。平移/旋转/斜放都表现为越界或某边余量变小，不再计算 dx/dy/角度，也不需要标定。
- **原因码**：`OUT_OF_ZONE`（越界像素超限）、`EDGE_MARGIN`（某边余量低于下限，消息里指出是哪一边）、`MULTI_OBJECT`、`NO_PRODUCT`、`LOW_QUALITY`。
- **界面**：
  - 「模板」页新增「按金样板生成安全区」：取 golden_mask 最大轮廓外接矩形，四周外扩 `max(24px, 最长边×3.5%)`，写入配方并自动把判定方式切到安全区；另有「框选安全区」（画框后回车/右键确认）和「清除」。
  - 「阈值」页顶部新增「判定方式」：形状匹配（旧）/ 安全区（像素）；安全区模式下可调「边距下限 px」（默认 10）和「允许越界 px」（默认 0）。两个值随配方保存，改了要点「保存阈值」。
  - 画布上安全区用黄色虚线框显示；判定叠加图上产品轮廓按 OK 绿 / NG 红，越界区域涂红，左上角用 ASCII 显示 `L/R/T/B px、min、out`（OpenCV Hershey 字体不支持中文，中文说明放在右侧面板）。
- **配方字段**：`judgeMode`（shape/zone）与 `zone{enabled,x,y,w,h,marginPx,overflowPx}`，坐标是原图像素；`FixtureRecipe.Validate` 在 zone 模式下不再要求标定和 mm 公差。
- **精度取舍**：1280 宽约 0.096mm/px，分割边缘重复性约 ±2–4px（≈0.2–0.4mm），可稳定判 1–3mm 级歪放，判不了 0.1mm；压损边界 10mm 足够。前提仍是固定相机、固定光源、锁曝光、ROI 只框针床。
- **修过的坑**：golden_mask.png 是三通道，直接 Threshold 会让 FindContours 抛 `Modes other than RETR_FLOODFILL and RETR_CCOMP support only CV_8UC1 images … 'img.type()' is 16 (CV_8UC3)`，生成前先转灰度；`FixtureStore` 之前按 `recipe.Model` 存盘，复制机种目录后会写回原机种，已改为以目录名为准。
- **验证**：复制 B001 为 ZTEST 测试。自动生成得到 1084×216 @ (95,341)（外扩 36px）；单张测试 OK：边距 L45 R43 T38 B40px、越界 0、21ms；手动画框并回车确认后安全区更新为 895×546 @ (106,0)。测试后 ZTEST 已删除，B001 配方恢复为测试前的 16:06:03 版本（未写入 zone）。
