# 针床定位 V2（YOLO 锚点）方案

> 状态：方案（未实现）
> 目标：用"学习到的锚点 + 几何比对"替代现在的"HSV 分割 + 金样板外扩"，把调试从"调阈值"变成"填一个容差"。
> 独立性：新增一个页签 + 一套独立目录，**不改** `FixtureAnalyzer` / `FixtureRecipe` / 现有"针床检测"页的任何判定逻辑。

---

## 1. 为什么值得单开一页

现有"针床检测"页的三个机制性问题（实测已确认）：

| 现状 | 后果 |
|---|---|
| 分割靠单帧 HSV 阈值 + 形态学 | 白色丝印、镜面高光把板面切成几十块，覆盖率天花板 ~69% |
| 几何量取"最大连通域外沿 1%/99% 分位" | 同一 OK 姿态两帧之间 L/R/T 就差 9–84 px，NG 信号只有 1–9 px |
| 安全区只能是轴对齐矩形 | 相机有 30–40° 俯角，世界矩形在图上呈梯形，近端切角 |

V2 换掉的正是"几何量"这一环：锚点由模型给出**稳定的框**，判定只剩"框中心离基准多远"。要调的参数从十几个变成 3 个（平移、旋转、置信度）。

---

## 2. 两个状态：标定 / 判定

```
[标定]  放一块确认到位的板 → 拍基准 → 每个锚点类取最高分框的中心 = 期望中心
[判定]  每帧推理 → 按类取最高分 → 与期望中心比 → OK / NG(原因码)
```

标定只做一次（相机、镜头、机种不变时永久有效）。基准帧同时留档，便于事后复核。

## 4. profile.json

```json
{
  "version": 2,
  "camera": { "index": 0, "width": 1920, "height": 1080, "fourCC": "MJPG", "exposure": -5, "gain": null },
  "model": "local",
  "infer": { "conf": 0.35, "nms": 0.5 },
  "calib": {
    "width": 1920, "height": 1080, "at": "2026-11-19 14:20:00",
    "anchors": [
      { "cls": "anchor_black",   "ex": 1466.0, "ey": 236.0, "w": 44, "h": 92 },
      { "cls": "anchor_label_a", "ex":  846.0, "ey": 262.0, "w": 96, "h": 46 }
    ]
  },
  "tolerance": {
    "shiftPx": 12.0, "rotDeg": 0.8, "scaleTol": 0.02, "rmsPx": 6.0,
    "minAnchors": 2, "okFrames": 2
  },
  "mmPerPixel": 0.107,
  "saveNgShots": true
}
```

- `model`：`"local"` = 用本机种 `model.onnx`；也可以写绝对路径或 `"global"`（用 `AppPaths.MyModelOnnx`）。
- `calib.width/height`：判定时若帧尺寸不一致，直接报 `CONFIG`（分辨率变了必须重标）。
- `mmPerPixel`：只用于把 px 换算成 mm 显示；判定仍以 px 为准，避免把不可靠的标定引进判据。

## 5. 判定内核（AnchorJudge）

纯函数，无 UI、无 IO，便于单测和离线跑图。

```
输入: PredictionResult r, AnchorProfile p
1) 按 RawCategory 分组，每类取 Confidence 最高的一项；低于 conf 的丢弃
2) required = p.calib.anchors[].cls
   hit = required 中命中的个数
   若 hit == 0                → NO_PRODUCT         （空治具/没放板）
   若 hit < minAnchors        → MISSING_ANCHOR     （列出缺的类）
3) 对每个命中锚点 i：
     dxi = cx_i - ex_i ,  dyi = cy_i - ey_i
   meanX = avg(dxi), meanY = avg(dyi)          # 整体平移（2 参数）
   resid_i = hypot(dxi-meanX, dyi-meanY)
   rms = sqrt(avg(resid_i^2))                  # 多锚点相对错动
4) 旋转/尺度（需要 >=2 个锚点）：
     v  = c2 - c1 ,  v0 = e2 - e1
     rotDeg = atan2 差（度）
     scale  = |v| / |v0|
5) 判定顺序（安全优先，NG 立即生效）：
     NO_CALIB → CONFIG → NO_PRODUCT → MISSING_ANCHOR
     → |meanX|>shiftPx 或 |meanY|>shiftPx      → SHIFT
     → |rotDeg|>rotDeg                          → ROTATE
     → |scale-1|>scaleTol                       → SCALE
     → rms>rmsPx                                → DEFORM
     → 否则 OK
6) 防抖：OK 需连续 okFrames 帧；NG 立即上报
```

### 为什么用"单平移 + 残差"而不是"两点相似变换"

两个锚点只有 4 个等式，而相似变换有 4 个未知数（tx, ty, s, θ）——**恰好定解，残差恒为 0**，当不了判据。
所以内核故意只解 2 参数的平移，剩下 2 个自由度变成残差，才具备"多点互不一致"的检测能力；旋转与尺度另用连线角度、连线长度比单独度量。3 个以上锚点时这套写法依然成立（残差自由度更多）。

## 6. 默认阈值与依据

| 项 | 默认 | 说明 |
|---|---|---|
| `shiftPx` | 12 px | ≈1.3 mm（按 0.107 mm/px）；首轮先用 12，再按实测抖动收紧 |
| `rotDeg` | 0.8° | 板宽 1635 px 上对应两端各 ~11 px |
| `scaleTol` | 0.02 | 两点间距 2% 变化 |
| `rmsPx` | 6 px | 多锚点互不一致 |
| `conf` | 0.35 | 固定机位、单机种，可以放宽 |
| `okFrames` | 2 | 防单帧抖动 |

**抖动自测**：页面持续统计最近 20 帧 OK 状态下 dx/dy 的标准差 σ，显示"建议容差 = 4σ + 2 px"并给一键套用按钮。现场不需要靠猜来定容差。

## 12. 风险与对策

1. **相机被旧页占用**：旧页离开页签会 `CloseFixCamera()`（`MainForm.Fixture.cs:1598-1611`），V2 沿用同样模式即可；两页不会同时持有设备。
2. **全局模型被重训覆盖**：机种目录留固定副本（见 §9.4）。
3. **锚点被压块/手遮挡**：报 `MISSING_ANCHOR`，并在结果里点名缺哪个类；选锚点时避开机构遮挡区。
4. **光照剧变漏检**：训练集覆盖 + 置信度可调；连续 N 帧缺检可上报"疑似光照/遮挡"。
5. **判据退化**：只有 1 个锚点时必须显式勾选"允许单锚点"，否则不准开连续检测（测不到旋转/尺度）。

### 14.1 现场使用步骤

1. **训练锚点模型**：在「数据采集/标注」页把三类锚点各标若干框（建议每类 ≥ 60 框、总图 150~300 张，含不同光照与轻微错位），类别名 `anchor_black` / `anchor_label_a` / `anchor_label_b`；训练完成后 `mymodel.onnx` 会部署到工作区根。
2. 打开「针床定位 V2」页 → 机种下拉选机种（或「新建机种」）→ 点「**复制当前模型**」，把 `mymodel.onnx` 复制进 `fixtures_v2/机种/model.onnx`（模型信息栏应显示 3 个类）。
3. 设相机（index / 1920×1080 / MJPG / 曝光 -5）→「打开相机」。
4. 把一块**确认放到位**的板放好 → 点「**拍基准**」。成功标志：基准信息显示尺寸与锚点数（≥2），`calib.png`、`calib_overlay.png` 落盘。
5. 拿 OK 件点「**判定一次**」，应显示 OK 且 dx/dy 在几像素内；再拿图4/图5 那种没放好的点「判定一次」，应报 `SHIFT`（或 `ROTATE`）。
6. 若 OK 件偶发 NG，按侧栏「抖动建议」把「平移上限」调到建议值（`max(3, 4σ+2)` 像素），再「保存容差」。

### 14.2 已知边界

- 判定只用**平移(2 参数) + 残差 RMS**，理由见 §5；旋转/尺度由基准里间距最大的一对锚点单独算，仅 2 个锚点时该对即全部锚点。
- 顶视相机看不出 Z 向浮高/翘边；图4/图5 已确认是平面平移，故够用。
- 分辨率与基准不一致会直接报 `CONFIG`，需重拍基准。
- `MmPerPixel` 字段已预留但当前判定仍全用像素阈值（mm 仅用于显示）。
- 未做真实相机冒烟测试（需现场设备）；两页共用一路视频流，切页签会关闭对方相机（沿用 `MainForm.Fixture.cs:1598-1611` 的模式）。

### 15.2 操作流程（一次成型）

1. 「识别目标」子页 → 点「**框选新目标**」→ 在板上框住稳定特征（白色丝印标签、黑色器件等）→ 弹框输入名字（如 `wifi`）→ 自动存为该类的一张样本。
2. 换不同板/不同光照重复上一步，每个目标攒 20~60 张；点「**训练并部署**」（60 轮、640 尺寸，CPU 约数分钟）→ 训练完 ONNX 自动复制为 `fixtures_v2/<机种>/model.onnx` 并重新加载。
3. 「检测范围」子页 → 点「**框选新范围**」→ 框住刚学的那个特征 → 自动命名「区域N」并**用当前画面自动采集参考模板**；把「绑定标签」设为该目标名（可留空则只做模板匹配）。
4. 按需调该区域的「匹配率≥」「搜索范围」「容许位移」；「必须通过」默认勾选。
5. 放过关的板 → 点「**判定一次**」：全部必检区域通过才 OK，任一不过即 NG，原因码显示 `ZONE`，并在画布上把区域画成绿框（过）/红框（不过），框上带匹配分。

建议至少 3 个分散区域（左前、右后、中部特征各一个），单靠一个区域只能证明“这一处没动”。

### 15.3 参数含义

| 参数 | 默认 | 含义 |
|---|---|---|
| 匹配率 ≥ | 0.90 | 模板匹配相关系数下限（`TM_CCOEFF_NORMED` 峰值）。不是“像素重合百分比”，对光照不敏感、对结构变化敏感；OK 件建议从 0.85~0.90 起测，观察实测值的余量 |
| 搜索范围 | 24 px | 在参考矩形四周外扩多少像素内搜索，容许的位移不超过它 |
| 容许位移 | 12 px | 匹配峰值位置相对参考位置的偏移上限 |
| 绑定标签 | 空 | 绑定后额外要求：模型检出该类、置信度达标、检出中心落在区域内、中心与匹配位置偏差不超容许位移 |
| 必须通过 | 是 | 不勾则只记录不参与总判定 |

### 15.4 判定组合

`JudgeAnchorFrame`：有区域时先跑 `AnchorZoneJudge`，把区域结论合成 `AnchorVerdict`（原因码 `ZONE`「区域不匹配」）；有模型且已标定时再跑锚点判定（平移/RMS）。锚点模型不是必需——只学 2~3 个特征并绑定成区域，也能单独工作。

### 15.5 能力边界

- 模板匹配对**平移**极敏感，对旋转/尺度变化不敏感于“匹配率”本身（本实现只补偿平移），所以板若明显旋转，请用锚点判定的旋转阈值，或把区域框得只含局部特征。
- 反光/手遮挡会压低分数；采样时应包含真实产线的典型光照。
- `LOW_MATCH` = 该特征没找到（没放板、放错位置、被挡）；`SHIFT` = 找到了但位置偏了。两者都判 NG，原因码可区分配查。
- 模板存的是**参考帧灰度**，若现场把相机/曝光改掉，需要重新「采集参考」。
